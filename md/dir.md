Today, I made some changes to the contract to ensure that users can mint an NFT only once per event. Each event represents a single token, with the NFT serving as a souvenir and having no intrinsic value. However, I realized that this design model limits scalability and business opportunities.

I am considering an alternative approach where NFTs are minted when a user buys a ticket. This would allow me to differentiate between ticket types, such as VIP and normal tickets, and reflect the multiple token functionality of ERC1155.

This is a significant change, as the current design—where one event corresponds to one token—does not support this new model of multiple ticket types. I may need to map each token to a specific ticket type instead of associating one token with a single event.（I not done yet
